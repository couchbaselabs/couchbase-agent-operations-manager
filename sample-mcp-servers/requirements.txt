# Pin only the top-level package; let pip resolve compatible
# starlette/uvicorn/etc. that `mcp` itself depends on.
#
# 1.29.1 is the floor, not a preference. Up to 1.29.0, FastMCP's `Settings`
# model annotated its `lifespan` field with a forward reference to `FastMCP`,
# which is defined later in the same module - so the model was never
# completed and pydantic-settings 2.15+ warns
# `IncompleteFieldDefinitionWarning: Field 'lifespan' has an incomplete
# definition` on every boot. 1.29.1 added the `Settings.model_rebuild()` the
# warning asks for. Staying on 2.x is a separate decision: mcp 2.x renames
# FastMCP to MCPServer and is a breaking API change, not an upgrade.
mcp==1.29.1
