Couchbase Agent Operations Manager has been deployed.

1. Get the dashboard URL:
{{- if eq .Values.ui.service.type "LoadBalancer" }}
   It may take a few minutes for your cluster to assign an external IP.
     kubectl get svc {{ include "aom.uiServiceName" . }} -n {{ .Release.Namespace }} -w
   Then browse to https://<EXTERNAL-IP>

   If that IP doesn't respond (common on local/dev clusters - Docker
   Desktop, kind, minikube - which can assign a LoadBalancer IP that
   isn't actually reachable from your host, even though kubectl sees it
   fine), port-forward instead:
     kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "aom.uiServiceName" . }} 8443:443
   Then browse to https://localhost:8443
{{- else if eq .Values.ui.service.type "NodePort" }}
     export NODE_PORT=$(kubectl get svc {{ include "aom.uiServiceName" . }} -n {{ .Release.Namespace }} -o jsonpath='{.spec.ports[?(@.port==443)].nodePort}')
     export NODE_IP=$(kubectl get nodes -o jsonpath='{.items[0].status.addresses[0].address}')
     echo "https://$NODE_IP:$NODE_PORT"
{{- else }}
   ui.service.type is ClusterIP - port-forward to reach it:
     kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "aom.uiServiceName" . }} 8443:443
   Then browse to https://localhost:8443
{{- end }}
{{- if .Values.ingress.enabled }}
   Ingress is also enabled for: {{ range .Values.ingress.hosts }}{{ .host }} {{ end }}
{{- end }}

2. The certificate is self-signed by default (tls.mode=generated) - your
   browser will warn you the first time. See the `tls` section of
   values.yaml for how to supply your own certificate instead.

3. The bundled Couchbase admin password and the three seeded agent API
   keys were generated randomly on first install (unless you set them).
   Read them back with, for example:
     kubectl get secret {{ include "aom.authSecretName" . }} -n {{ .Release.Namespace }} -o jsonpath='{.data.API_KEY_ADMIN}' | base64 -d
   (keys: COUCHBASE_PASSWORD, API_KEY_SUPPORT_AGENT, API_KEY_FINANCE_ANALYST,
   API_KEY_ADMIN). See SECURITY_HARDENING.md in the main repository.

4. The first login has no password set - visit the dashboard and follow
   the initial-admin-setup flow for "{{ .Values.operationsManager.auth.defaultAdminUsername }}".

5. Couchbase provisioning runs as a Job (a Helm post-install/post-upgrade
   hook) and is safe to ignore once it shows Completed:
     kubectl get jobs -n {{ .Release.Namespace }} -l app.kubernetes.io/component=couchbase-init

Check overall status any time with:
  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}
